MCP seat cutover: Node names to Rust product operations

The launched session binds identity and project on every stdio and HTTP call.
Do not copy Node project, actor, root, envelope, packet-ACK or factory selectors
into Rust arguments. Unknown fields refuse. Discover the actual Rust catalogue
with tools/list; se schema describes the same operation DTOs and output families.

Node tool                     Rust tool / argument mapping
stateengine_resume            stateengine_resume: limit, byte_budget, since and
                              governing_cursor. Follow each returned Rust cursor
                              on its own stream; Node cursors are not portable.
stateengine_msg_list           stateengine_msg_list: view="unread" (default) or
                              "all", box="inbox" (default) or "sent", limit,
                              cursor, full, preview_chars, from and kind.
stateengine_msg_read           stateengine_msg_read: msg_id and optional budget.
stateengine_msg_send           stateengine_msg_send: to, body, kind, refs,
                              reply_to, idempotency_key and optional work below.
stateengine_project_status     stateengine_status: {}.
stateengine_atlas_query        pending-L6; no Atlas tool is advertised yet.
                              Bind its consumer and final arguments after L6.

Every mutation send requires an explicit idempotency_key. Retry the unchanged
arguments with that same key; changing the message, recipients or action with
an existing key refuses. Transport JSON-RPC IDs are not mutation keys. A receipt
means committed; recipient delivery and read state are separate facts.

Full-body lists are read-only. Read by ID to mark a complete body read. An
oversize read refuses before its mark; request a larger supported CLI budget,
or call stateengine_msg_ack to acknowledge without a body. Repeated read/ack
and stateengine_msg_dismiss retain their original natural receipt. All IDs and
references come from this project's Rust receipts; refs are event IDs, while
reply_to names a message ID. The optional list cursor and disposition remain
explicit in the returned page; never treat a bounded page as an empty inbox.

A direct send names a registered recipient in to. A floor send uses to="floor"
and work={"action":"finding","addressees":["<registered agent ID>",...]}.
Map Node work_action to work.action and addressees to work.addressees. Use 1..20
distinct registered agent IDs from the bound project. Actions are admit, assign,
return, question, ruling_request, ruling, finding and notify. Floor finding
requires both kind="finding" and work.action="finding"; return commonly uses
kind="question" and work.action="return". Actions label a message's purpose;
they grant no authority. One floor message has one ID/body and independent
recipient read/dismiss state. Each recipient sees that same canonical message.
Floor rows name for_recipient, whose delivery/disposition is shown; owner
inspection can choose another recipient with the CLI msg list --to filter.

Rust retains the 32 KiB UTF-8 body bound and at most 20 refs. List limits are
1..100, preview_chars is 0..4000, and msg_read budgets are 512..1048576 bytes.
Resume budgets are 1024..1048576 bytes. Complete MCP envelopes have an additional
transport bound; follow the typed refusal rather than infer truncation. Node's
quiet, supersedes, to_project, bulk-dismiss and legacy msg_id retry fields are
not Rust inputs; this cutover does not add factory compatibility aliases.
