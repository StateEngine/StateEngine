# Product operation allowlist

This is the shipped Rust product's operation inventory. CLI, MCP, IPC and linked calls derive from one synchronous core registry, with async custody execution in the host. The reconciled rows contain **58 operations and 24 MCP tools (19 core, 5 optional Atlas)**; executable counts are generated from the registry; a crate cannot introduce an unlisted public operation. This document is a design contract, not a running implementation or journey verdict. The Node repository keeps its private factory engine; no fleet cutover/import or CLI-only factory adaptation is part of this build.

## Journeys and row conventions

| ID | Outcome, with Claude and Codex on Windows, macOS and Linux |
| --- | --- |
| J1 | Install from a real download; discover the installed version from a fresh terminal. |
| J2 | Adopt an existing repository; an agent does a real task while user files and Git history survive. |
| J3 | Come back after closing everything; resume the original conversation with demonstrated recall. |
| J4 | Two agents hand off through messages; the user observes the handoff and its result. |
| J5 | Remove and uninstall cleanly; stop owned instances, remove owned integration/credential exposure and restore managed PATH entries while preserving user work. |

`support Jn` means a recovery, inspection or privacy operation supports that journey; it does not add a sixth journey. `optional Jn` means useful to that journey but not an acceptance prerequisite. Atlas is optional and cannot hold up any journey.

* **Name** is the stable registry key, not a Rust symbol or an old command alias. CLI paths omit the leading `se`. Bracketed arguments are optional; alternatives in one cell are explicit typed variants of one operation.
* **MCP** names are exact and include `stateengine_`. `none` always gives a reason. All listed MCP operations also have an in-process typed entry point; transport-specific framing does not create a second implementation.
* **Auth** is `owner`, `session` or `either`. Owner means machine credential plus the OS user's verified authority; human-only approval, destructive removal and secret erasure additionally require an interactive terminal outside an agent process tree. A label or an `--actor` flag never supplies authority. Session means a verified, unrevoked bound capability on external transports, or a generation-bound in-process handle in embedded SE Code. Embedded binding issues no credential events. Either accepts either authority subject to the scope rules below. These checks guard mistakes/drift; they are not proof against a determined agent running as the same OS user. The three public metadata operations (`meta.version`, `meta.help`, `meta.schema`) additionally permit anonymous access; they disclose no private state.
* **Effect** is `read`, `write` or `custody`. Read has no durable domain mutation. Write changes durable state or writes an explicitly requested owned artifact. Custody starts/stops/controls a runtime, agent or listener and records its effects. A combined effect lists each typed variant's behavior; it never licenses a read to mutate silently.
* Inputs name semantic fields, not arbitrary JSON. Every operation has a closed typed input, rejects unknown fields and carries bounded strings/pages. Authority is supplied by the host, never deserialized from input. IDs are opaque typed IDs; a friendly agent name resolves through the registry before dispatch. Optional input syntax here does not make required fields optional in generated schemas.
* Outputs below are named contract families. Each serializes with an explicit `schema` version. `Read<T>` distinguishes present, absent, unreadable and unknown; `Page<T>` includes window, completeness, omissions and continuation. `Receipt` carries event/idempotency and committed-state facts; delivery or read status is a separate fact. A command does not turn refusal into success because it returned JSON.

## Scope shared by every operation

Owner project selection is explicit `-p/--project`, then `SE_PROJECT`, then an exact lookup of the registered repository containing cwd, then configured default, then the sole registered project; otherwise refuse with the available choices. For nested registrations use the closest registered ancestor; unreadable/ambiguous registration refuses rather than falling through to an unrelated default. Lookup never registers or creates anything. Explicit selection remains available from outside a repository. Only `init --repo DIR` accepts a repository-root override, defaulting to cwd. `--home` selects the product state home, not a project or actor. Conflicting legacy root flags refuse.

A bound session's project and actor come exclusively from its capability: no cwd/default fallback and no MCP `project_id`, `agent_id` or authority override. A conflicting CLI `-p` refuses. Agent selectors shown below are owner-CLI selectors unless the row explicitly creates a new identity or permits creator control. On other session calls, self is implicit; granting a session a tool does not grant owner powers. Session reads cannot expose another agent's private continuity or inbox; project-shared decisions and authorized history remain readable. Message recipient names are destinations, not actor overrides. Agent creation requires the current `agent.<A>.can-create` grant for the authenticated agent A, and its new identity is never the caller's authority.

Creator control is the sole additional agent-target exception: an agent A currently holding `agent.<A>.can-create` may launch, wake and stop an agent whose immutable recorded `created_by` is A in the same project. MCP uses optional `target_agent_id` for that target, distinct from the authenticated actor; CLI resolves its AGENT selector to the same typed target. Launch/stop without this field retain their existing self rules; wake requires an explicit target. Non-self targets not directly created by A are owner-only, including grandchildren, other coordinators' helpers and imported agents with unknown creators. Grant revocation removes creator control; rename/profile changes do not change creator. `--all` remains owner-only. Readback/status must not use this exception to expose another agent's private continuity or inbox.

Owner reads of an agent's inbox/history are inspection, not evidence that the recipient read a message. Read/ack/dismiss markers are attributable to the authenticated recipient; the owner cannot manufacture an agent's read witness. Self-service message disposition therefore refuses when the current owner identity is not that recipient. Owner-only all-project/all-agent flags do not appear in bound MCP schemas.

Global flags are not accepted inertly by unrelated operations.

Plain `se init` (including `--repo DIR`) is managed setup and writes nothing inside the repository; it registers existing repositories idempotently. Its human output ends with the scoped first-launch command, which also appears as literal argv in JSON. Run that command to start the saved initial agent. Managed Claude/Codex launches receive their wiring through launch flags rather than repository/global integration edits. Preserve unrelated files and Git history. Provider is the closed `claude`/`codex` choice; default permissions preserve sandbox/approval behavior, and full bypass requires a saved opt-in profile by name. The three doctor variants are mutually exclusive; configuration repair never rotates credentials or restores history, and `--fix` is not an arbitrary filesystem writer, SQL console or grant to weaken those defaults. Remove preserves history; erasure is the separate explicit operation below.

Launch resumes the saved conversation by default; `--new` starts another conversation for the same durable agent. If a saved resume reference cannot be verified, refuse with its remedy instead of silently starting fresh. Launch auto-starts a standalone runtime when necessary. Provider/model overrides must be compatible with the chosen conversation; changing provider cannot pretend to resume a different provider's conversation. Capture and process facts remain separate from task completion. `--preview` never binds, launches, revokes or acknowledges a session. No polling, process-per-agent engine or legacy launch spelling is implied by these operations.

Resume defaults to 32,768 UTF-8 bytes for its JSON reply and 20 rows per section; `--budget` accepts 1,024–1,048,576 and `--limit` accepts 1–100. `--since` accepts only the same admitted principal and target's resume cursor. Current ratified project decisions are governing law, read through a targeted port under the session's existing visibility; pending, withdrawn, superseded and private proposals do not become visible through continuity. An incomplete ruling page includes `decisions.next_cursor` for `--governing-cursor`; packet clipping or a refused source remains explicit, with a count or a named unavailable count and a legal retrieval command. Listing context never acknowledges issued packets or marks mail read.

Listing never creates or changes read/delivered markers, including `msg list --full` / MCP `full: true`; `message.read` remains the recipient-marking path. Full mode stops before a body that would exceed the page's byte cap and returns continuation instead of silently truncating that body; the explicit too-small-budget remedy applies when even the first full item cannot fit. Owner full-body inspection covers any message in the selected project; a session can list full bodies only for messages it sent or received. Delivered, read, dismissed, replied and task-completed are distinct; internal mail settlement records actual consumer observations rather than manufacturing a public completion verb. No PostgreSQL mirror retry flags or repair commands survive into these inputs. A session may propose replacement text but cannot activate it by setting `--supersedes`. Working-state and decision compare-and-set conflicts require a reread, not an unconditional overwrite retry. Decision list's CLI `--id ID` and MCP `id` are the same optional typed exact-ID filter. With ID alone, a complete empty page denotes an absent ID; additional pending/history filters can yield zero matches without claiming the ID is absent. Decision show uses the ID-only lookup and exposes its `Read<Decision>` result; unreadable/unknown outcomes remain distinct.

Integration secrets never travel in process-visible argv, logs or public receipts. A capability is verified per call, including a multiplexed connection; invalid/revoked credentials never fall back to the owner. Anonymous/incognito context is a neutral adapter result without private history, not a route into the authenticated context operation. `session.begin` and provider hooks cannot bind from a claimed session ID alone. The session-start hook is read-only because launch/begin establish the binding first; an unmanaged adoption must complete that binding before private context is returned. Hook failure may preserve the provider's startup availability, but exit 0 is never proof of capture.

Managed agent custody uses the host and exact native-instance rechecks; launch may auto-start through the private runtime bootstrap. There is no public daemon command or arbitrary process.start/control/list service. A hostless transport reports unavailable or uses its admitted bootstrap path before dispatch, retaining the request identity and any pending result.

Library lifecycle methods (`open`, capability verification, tool catalogue/call, mail subscribe/settle, drain/reopen) are typed service/transport seams, not extra user operations or generic dispatch backdoors. Mail delivery and capture catch-up are internal work under the admitted session authority. No public `msg deliver`, `mail wait`, arbitrary hook event, Codex hook fork, generation-restart command or remote-process verb is admitted here; managed Codex uses app-server and SE Code uses direct library calls.

Atlas is built after journeys and live handover and never holds a milestone. Atlas is compiled only into the standalone `se`; it is disabled by default and enabled by `atlas.enabled = true` in config.toml; in embedded SE Code that setting returns feature-unavailable. Its operations are exposed only when compiled in and enabled; status reports unavailable/disabled/absent/updating explicitly. `config.set` writes that key to config.toml like any general setting; the standalone host reads it on its next config read or restart. Cold indexing is a transient capped child. There is no project settings layer or second Atlas administration family. Reads never trigger an unbounded cold index, and optional resume enrichment is read-only and budgeted. Indexing owns a separate rebuildable code-only database; it is never the source of turns/messages/decisions. Disabled builds refuse explicit Atlas CLI invocations with an actionable feature-unavailable error and advertise no phantom tools.

Import keeps user identities, agents/profiles, messages/dispositions, decisions, working state, turns, conversation references and provenance, mapping legacy IDs to typed IDs without promoting dead process IDs or old credentials to live authority. Imported agent aliases may remain lookup data, but there is no alias-creation operation: stable IDs and rename cover new naming. ## Generation, errors and execution boundaries

The rows become one `ops![...]` registry: operation metadata declares CLI path(s), MCP name or explicit reason, auth, effect, runtime requirement and API introduction version. Each operation has one closed input type, one versioned output type and one executor. CLI, MCP and direct library callers share its validation, authorization and behavior, including hook-event variants. CLI-only and MCP-only reasons are registry metadata, not hand-maintained allowlists. No arbitrary extension loader or `tools(call=...)` escape hatch expands this set.

`tools/list` and `Host::tools` return that session's available rows and generated input/output schemas, respecting authorization/features. Catalogue exposure policy can vary without adding callable names. Help, schema export, protocol initialize/ping and non-private liveness are transport/discovery behavior; they do not acquire history through anonymous metadata access. Endpoint routing/host migration details, cache sizes and FULL/NORMAL durability choice belong in host/store design; this allowlist does not settle them or authorize a second write implementation.

Reads may use direct store readers; writes share the canonical store transaction implementation whether reached through the host or an admitted hostless CLI path. Runtime ownership is distinct from owner authorization: a session-authorized launch still needs the runtime, while an owner read need not start it. Only the host migrates store schemas; newer stores refuse incompatible binaries with a remedy. Supported additive migrations apply automatically at sole-owner startup after verified pre-migration backup. An old running host refuses with `run se down first`; too-new/unsupported stores refuse. No approval token or manual migration step is required. Automatic backups run start-of-day and clean shutdown; the public manual backup and salvage operations are deferred. `se restore` is a separate human-only owner action selecting newest valid backup and preserving the corrupt source. `doctor --fix CHECK-ID` never rotates credentials or restores history and cannot claim unreadable data was repaired to zero.

All operations return structured errors with code, class, detail and remedy. Human rendering names a cause and legal next action; JSON goes to stdout, diagnostics to stderr, MCP reports the same structured error with `isError`. CLI exits are 0 complete (including measured absence/zero), 1 failed/refused, 2 incomplete, 3 unreadable, 4 unknown target and 64 usage. `Read<T>` state and list completeness remain in the payload even when a renderer selects a nonzero exit. Session context and Claude hook output retain their versioned consumer framing instead of ordinary command JSON.

The output families retain explicit decoder boundaries: setup's `stateengine-init/v1` profile, stop's `seat-stop/v1` receipt/resume reference, and SE Code's `secode.session-context-v1` contract remain recognizable to their supported consumers or require an explicitly negotiated new version. The SE Code context preserves packet/project/agent/session/provider identity, assembled model input, UTF-8 byte size, truncation, continuity and warnings; a generic resume object is not a substitute. Supporting a stored handle or DTO version does not execute an old CLI/MCP name.
