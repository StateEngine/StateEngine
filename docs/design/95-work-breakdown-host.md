# 95. Work breakdown — se-host

The separate [remote program](45-remote-clients.md) delivers three ordered outcomes: one-command SSH connect/reuse with native agent identity and mail, real return-mailbox replies, then independent agent and link revocation. [47](47-r0-contract.md) requires real consumer and process-boundary review of each complete outcome; a unit test or receipt alone is insufficient.

Round-2 planning input for the project maintainer, 2026-10-30; assembled base `f25ca90`.
**No code, tests or build permission. The operator approves the full design before
implementation.** The accepted [section 40](40-host-runtime-and-harnesses.md)
and [OPS inventory](../OPS.md) govern; sections 80 and 90 are the shared budget
and acceptance chapters. These are planning tasks, not mandatory separate
landings or new assignments.

Dependencies: **F** = se-types identities, errors, receipts and checked codecs;
**S** = se-store snapshots, writer, leases, keyed transactions and runtime-owner
facts; **P** = se-proc identity/security, ProcessRuntime, evented stdio, transfer,
runtime bootstrap and shared file-watch service; **K** = se-core's synchronous
registry, authorization, session/mail/capture and continuity operations;
**E** = the SE Code API's HostFactory/Host implementation contract and the native
HostServices/HandoverServices supplied by SE Code. **Q** = independent section
90 reviewers, external journey runner/action map and packaged artifacts.
The native backend, native queue implementation, kernel/store internals and
permissive API stay with those owners; this chapter consumes them. The shared
registry has **58 operations, 24 MCP tools (19 core + 5 Atlas), 52 event kinds
and 42 application tables (including resume_heads)/30 triggers**, and user-state import has six families. H18 consumes
those generated contracts; none of these counts creates a host-local registry.
Embedded handles issue no credential; settings are flag > env > config.toml >
default, with no project layer. No migration-approval, salvage, temporal decision
summary, public process.* or store.backup operation is implemented here.

H01 alone owns the se-host manifest, lib/model facade and module registration.
Other authors own their listed leaf files; facade moves and Cargo.lock changes
are serialized with the relevant integrator. Paths below are inside
`crates/se-host/src/` unless stated otherwise. The proposed layout refines
40 §2.1, with no planned source file above 500 lines. Estimates are production
Rust lines excluding external implementations and reviewer tests. Agreed ports
permit parallel authoring; missing consumers block their behavior witnesses,
not unrelated work. Authors write no tests or runner changes (90 §1).

Witness: real SE Code linked open/bind plus standalone invocation, public-build dependency exclusion and outside helper/process inventory; Q checks the existing build/dependency rules. A compiling stub is not the linked behavior.

**H02 — Blocking bootstrap, wire and client proof (~850).** Files: `client/{endpoint,lease,wire,auth}.rs`. Depends H01, F/S/P and K's admitted operation DTOs. Satisfies 40 §§5/7.1–7.2, 80 B7 and 90 §3 T2/T3/T17/T21/T22: synchronous generation-free discovery/direct-lock acquisition, native server/peer verification, challenge MAC, bounded framing and original-key readback. Share wire/auth primitives with host consumers; never route an invalid session to owner or a failed IPC write to a competing direct writer. Witness: installed CLI with/without a host, foreign/squatting peers and revoked credentials, plus outside store/writer-stamp readback, mismatched-API down/lost-reply witnesses on all three OSes and B7's 30 samples per named command.

**H03 — Factory preparation and first activation (~450).** Files: `runtime/{factory,activation,executor}.rs`. Depends H01/H02 and F/S/P/K/E. Satisfies 40 §§4–5/10.2, 80 B1/B2/B3 and 90 §§2–3 T10/T17: shared dispatcher for every hosted entry point with separate bounded blocking-pool planning/continuation jobs around an executor-only Completion await, read-only prepare, actual lease/endpoint/listener ownership, registered G/services before activation, and the normal embedded first-owner/session joint FULL maintenance commit before writer startup. Bound first-bind waiting by FIRST_BIND_WINDOW = 10 s from activate returning Prepared, using an absolute Instant deadline rechecked on resume, separate from CallOptions.timeout: expiry with no bind or definite refusal within the window fences and joins accepted work, then uses ordinary owner-only FULL admission before the writer. Status becomes ready; a later first bind takes the ordinary session-activation path like a second bind, without an expiry failure to SE Code; a known joint commit is retained instead and unknown outcomes preserve both keys. Activating remains drainable without inventing a writer or binding. Prepare reads schema/plans without mutation; activation as sole owner verifies the pre-migration backup and automatically applies supported additive migrations before publishing readiness. A live older host requires `se down` first; absent store yields structured setup-required to H13's per-workspace pre-TUI repository trust hook (only accepted workspaces invoke bundled managed owner se init --repo DIR, then re-prepare; declined workspaces are never registered; public GitHub stub silently skips init), unsupported/too-new schema refuses with the upgrade/restore remedy. No approval fingerprint or maintenance-only migration API. Explicit init/schema time is outside B2 and measured separately; real runtime.owner/session binding and required migration/backup work stay inside measured B2; embedded binds mint no credential. Recovery, reconnect and scheduled backup wait until ready. Witness: actual SE Code first authenticated session response and independent owner/binding readback, existing/new/old-supported-store timing and J1/J2; outside backup/schema readback, failed-backup/no-migration and live-old-host/mismatched-API-down cases, with honest absent/unsupported refusal.

## Supervision and explicit handover cost

## Scheduling and completion

H01 freezes shared contracts/wiring first. H02/H04/H09 and the leaf transport
work can then proceed alongside their external owners; H03/H05/H06 join actual
custody, and H07/H08 join the provider/native producers. H10–H13 can run on
disjoint files once their ports agree. H14 joins safe supervision; H15/H16 join
both directions and every terminal fence path. One owner serializes each shared
file; source-module registration remains H01's job. A blocked native, SE Code or
store path does not stop unrelated leaves, and cannot be replaced by a fake
success. The project maintainer assigns owners and assembles complete candidates.

**QH — Integrated host acceptance (0 new production lines).** Files: none newly owned; fixes remain with H01–H20, reviewer cases/runner with Q. Depends all required host joins, F/S/P/K/E and real artifacts. Satisfies 40 §§10–12, 80 B1–B9 and 90 §§1–3/5: J1–J5 on Windows/Linux/macOS with real Claude and Codex, embedded/standalone and attended/headless mirrors, public-boundary cases where journeys cannot reach. Measure B1 ≤30 MB, B2 ≤100 ms through first authenticated bind/continuity, B3's 0/1/0 process counts, B4 ≤25 MB after real work, B5/B6 idle, B7's 30 actual samples/command, B8's separately timed quiescence/cutover and B9 hosted NORMAL msg send/working-state set/hook claude stop p95 ≤20 ms. E3 separately measures `decision ratify|reject|retract|supersede`, `agent add`, `config set agent.<A>.profile|model|can-create` and `init` with the FULL bound p95 ≤75 ms on Windows with Defender. All five real-provider journeys in both compositions on all three OSes are required before alpha; borrowed native Mac qualification follows section 90's campaign and is never a cross-compile claim. Atlas is compiled only into the standalone `se`; it is enabled by default and can be disabled with `atlas.enabled = false` in config.toml; a host without an installed Atlas controller reports it unavailable. Atlas follows journeys/handover and never holds a milestone. Missing runner maps/probes or unreached modes remain unqualified; authors add no tests, gates or runner edits.
